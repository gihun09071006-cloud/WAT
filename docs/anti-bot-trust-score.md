# 안티봇 신뢰도 스코어 — 설계서

> **왜 관문인가**: 봇 완료가 fill에 섞이면 ① 광고주 ROI가 붕괴하고(§1 생존 조건) ② CPQ 측정이 거짓이 되며
> ③ 봇 Spark가 정직한 유저의 상환 풀(S)을 희석한다(§15). CPQ 실측(A1)의 **전제**다.
> 구현: `trust_score.py` · 테스트: `test_trust_score.py` (16개 통과).

## 1. 핵심 원리 — 플레이가 아니라 **출구**를 막는다

```
봇도 플레이하고 Spark를 벌 수 있다.  →  돈이 나가는 유일한 길목(월간 Spark→WAT 상환)에서만 차단.
```

이게 구조적 우위다:

- **비용이 싸다**: 실시간 플레이마다 캡차를 때리는 게 아니라, **월 1회 상환**이라는 단일·배치·고정밀 결정점에서만 무겁게 분석한다. 광고 네트워크보다 유리한 지점.
- **UX를 안 망친다**: 인간 유저는 마찰(캡차·KYC)을 거의 안 본다. Web3 초보도 지갑 개념 없이 진입(§12).
- **한 번에 셋을 지킨다**: 광고주 ROI · 정직한 상환자 환율 · CPQ 측정 무결성.

## 2. 신뢰도 스코어 — 연속값 [0,1], 이진 밴 아님

가중 앙상블. **행동 신호가 최고 가중치** — 비행기 슈팅은 조준·회피·타이밍이라는 풍부한 행동 바이오메트릭 표면이라, 우리의 최고 봇 탐지 신호다.

| 신호 | 가중치 | 소스(예시) |
|---|---|---|
| behavioral_humanity | 0.24 | 터치 다이내믹스, 반응시간 분포(로그정규 vs 상수), 스킬 곡선, 서카디안 리듬 |
| device_integrity | 0.22 | Play Integrity/App Attest, 에뮬레이터·루팅 탐지, 센서 엔트로피 |
| network_reputation | 0.14 | 레지덴셜 vs 데이터센터/VPN/프록시, ASN 클러스터 |
| account_maturity | 0.14 | 계정 나이 + 정상 진행 속도(즉시 만렙 = 의심) |
| graph_independence | 0.14 | 레퍼럴/상환 시빌 클러스터 비소속 |
| ad_interaction_quality | 0.12 | "부품 스캔" 진성 참여 vs 자동 클릭 |

**하드 플래그**(연속 신호 위에 곱/캡):
- 기기당 계정 수 > 3 → 스코어 ×0.30 (기기 팜)
- 지오 벨로시티 위반(불가능한 이동) → 스코어 ≤ 0.40

## 3. 티어 & 위험기반 상환 게이트

마찰은 **티어 × 요청 금액**에 비례. $3 인간은 KYC를 안 본다.

| 티어 | 스코어 | 상환 |
|---|---|---|
| **Trusted** | ≥ 0.75 | 전액 승인 |
| **Provisional** | 0.50–0.75 | 에폭당 $5 한도. 초과분은 단계 인증 |
| **Restricted** | 0.25–0.50 | Spark 획득만 가능. 상환하려면 단계 인증(어필 경로) |
| **Blocked** | < 0.25 | 봇 확정. S에서 제외, §11 공개 지표에 집계 |

### 단계 인증 사다리 (필요할 때만, 점진적)
```
L0 수동 신호만 (마찰 0)  →  L1 기기증명+행동(비가시)  →  L2 게임 내 챌린지(특수 보스 인증)
                                              →  L3 고액 상환 시 인격증명/경량 KYC
```
마찰은 상환 **금액·위험**에 스케일. 균일 적용 아님.

## 4. 시빌 경제 설계 — 봇을 ROI-음수로

- 상환 신뢰는 **진성 플레이로 시간에 걸쳐 누적** → 팜이 즉시 1만 계정을 상환가능하게 못 만든다.
- 계정당 보상 상한(~$3/월, §8) × 신뢰 누적 시간 → 계정생성+기기+레지덴셜프록시 비용 감안 시 대량 파밍이 수지 안 맞음.
- **결정적**: 봇이 Spark를 벌어도 **상환 게이트에서 걸러져 S에 진입 못 함** → 정직한 유저 환율 불변(§15). 봇은 기껏해야 faucet만 부풀리고, 그건 발행 브레이크(§15 ①)가 잡는다.

## 5. 오탐(false-positive) 처리 — 최악의 오류

진짜 인간이 번 보상을 막는 것 = 신뢰 사망. 그래서:
- **미확정 봇은 하드밴 금지** → Restricted(어필 가능)로.
- Provisional은 한도 내 승인 + 초과분만 단계 인증 → 대부분의 애매한 인간이 통과.
- 확정 봇(강한 다중 신호)만 Blocked.

## 6. 관측 지표 (§11 히든카드 연동)

`pool_integrity()` 산출:
- **봇 차단 N** (blocked_accounts) → 메인 화면 공개 → "유저가 안티봇이 된다"(§11)
- filtered_rate, 정직한 S, 신뢰 스코어 분포, 상환 승인율, **오탐율**(최소화 대상)

## 7. v1 → v2 로드맵

1. **v1 (현재)**: 투명 룰 기반(`trust_score.py`). 런칭 가능·감사 가능. 가중치·임계값 튜너블.
2. **v2**: 데이터 축적 후 이상탐지/그래디언트부스팅 앙상블로 진화. 룰은 설명가능 백스톱으로 유지.
3. **연동**: Tier 1 프로토타입(C1)부터 `bot_filtered_rate` 계측 → CPQ 측정을 진성 완료 위에서만 집계.
