# Web3 지갑 추상화 — 지갑 없이 진입 (C5)

> **§12 약속**: "Web3 초보도 지갑 개념 없이 진입 가능해야 한다." 이 문서는 그걸 아키텍처로 만든다.
> 구현: `onboarding.py` + `test_onboarding.py`(7개). 리서치 기준 2026 지형.

## 1. 원칙 — 2계층: 게임러는 냅두고, 보상러만 지갑

```
둘러보기 → 플레이(오프체인 Spark, 지갑 0) → [보상 원할 때만] 지갑 단계 → (고급) 자가수탁 export
```

- **그냥 게임할 사람**: 지갑 0, 평생 안 만짐. Spark는 오프체인이라 플레이·상점 소비에 지갑이 필요 없다.
- **보상 원하는 사람만**: 그때(만) "보상 받으려면 지갑 단계" 안내 → 지갑이 뒤에서 생성. 시드문구 화면 없음.

### ⚠️ 가스 정책 (founder 결정) — 운영사는 가스를 대지 않는다

- **가스는 유저 부담**, 단 **받을 WAT에서 차감**(ERC-4337 ERC-20 페이마스터). → 운영사 비용 0 **그리고** 유저는
  네이티브 가스 토큰(ETH 등)을 따로 살 필요 없음.
- **이 결정은 저렴한 체인을 강제한다.** 유저 월 보상 ~$3인데 L1 가스는 건당 $1~20 → 보상이 통째로 먹힘.
  따라서 **L2/앱체인(Base·Arbitrum·Polygon 등, 건당 몇 센트)** 은 선택이 아니라 **필수**.
- 상환은 **월간 배치(Redemption Epoch)** 라 Merkle 클레임·배치 트랜잭션으로 건당 가스를 더 낮출 수 있다.

## 2. 온보딩 상태머신 (`onboarding.py`)

| 상황 | 지갑 | 모드 | 가스 | KYC |
|---|---|---|---|---|
| 둘러보는 방문자 | 불필요 | none | — | — |
| 플레이 중(상환 전) | **불필요** | none | — | — |
| 첫 상환 $3 | 필요 | embedded | **유저(WAT 차감)** | — |
| 고액 상환 $500 | 필요 | embedded | 유저(WAT 차감) | ✅ |
| 자가수탁 export | 필요 | self_custody | 유저 | (고액 시) |

`trust_score`(상환 자격 게이트)와 조합: trust는 **상환 가능 여부**, onboarding은 **지갑이 어떻게 동작하나**.

### 지갑 "연동" 방식 — 둘 다 운영사 비용 0

| 방식 | 마찰 | 권고 |
|---|---|---|
| **임베디드 자동 생성**(이메일/패스키) | 낮음 — "계정"만, 시드문구 없음 | ⭐ **전환 유저 이탈 최소** |
| 외부 지갑 연결(메타마스크 등) | 높음 — 설치·시드문구, 초보 이탈 | 옵션(고급 유저) |

> 전환하는 유저 = 광고주·경제가 가장 원하는 유저. 여기서 이탈시키면 아까우니 **임베디드 + 가스 유저부담**을
> 기본으로, 외부 연결은 고급 옵션으로. (`embedded_wallet` 플래그)

## 3. 4개 추상화 레이어

### ① 로그인 — 시드문구 제거
이메일 · 소셜(OAuth) · **패스키**로 로그인. 임베디드 지갑이 뒤에서 키를 관리. 유저는 "계정"만 인식.

### ② 가스 — 운영사는 안 대고, 유저 WAT에서 차감
**ERC-4337 + ERC-20 페이마스터**로 가스를 **유저의 WAT에서 차감**. 운영사 비용 0, 유저는 ETH 불필요.
저렴한 체인(L2/앱체인)이 필수 전제(위 §1 경고). WAT 상환만 온체인이라 가스 접점은 여기 한 곳뿐.

### ③ 커스터디 — 비수탁 기본, 이탈 경로 보장
**MPC/패스키 기반 비수탁**이 기본(유저가 실질 통제, 운영사 단독 키 아님). 고급 유저는 언제든 **self-custody로
export** — 진짜 소유(§3 "파는 것은 유저와 거래소 사이")를 코드로 보장.

### ④ 복구 — 시드문구 없는 복구
소셜·이메일·패스키 복구. 분실 = 시드문구 24단어가 아니라 로그인 재인증.

## 4. KYC 점진 — 온보딩 0, 고액에서만
- 온보딩·플레이·소액 상환($3/월, §8): **KYC 없음**.
- **고액 상환(≥ $200 누적)에서만 step-up KYC** — `trust_score`의 위험기반 게이트와 결합.
- Web3 초보 진입 마찰 최소화 + 컴플라이언스 임계만 방어.

## 5. 벤더 지형 (2026 리서치)

| 유형 | 후보 | 비고 |
|---|---|---|
| **임베디드 지갑** | **Sequence**(게임 특화·엔진 SDK) · **Privy**(Stripe) · **MetaMask Embedded**(구 Web3Auth·Consensys) · Para · Magic · Openfort · Coinbase Smart Wallet | 소셜/이메일/패스키 + 비수탁 |
| **AA · 가스 스폰서** | MetaMask(대시보드 내장) · Alchemy · Pimlico · Biconomy · ZeroDev | ERC-4337 페이마스터 |
| **엔진 연동** | Sequence · thirdweb | Unity/Unreal SDK |

> **권고**: 게임 특화 **Sequence** 또는 **Privy**로 시작 (Unity SDK + 소셜 로그인 + ERC-20 페이마스터).
> 지갑 생성은 **보상 상환 시로 지연**, 가스는 **유저 WAT에서 차감**(운영사 미부담), 저렴한 L2/앱체인, export 경로 상시 개방.

## 6. 컴플라이언스 접점

- 비수탁 기본 → 운영사가 유저 자산을 직접 수탁하지 않음(수탁 라이선스 부담↓, §jurisdiction과 연동).
- KYC는 고액 상환에서만 → 프라이버시·마찰 최소, AML 임계 방어.
- 관할별 지갑·수탁 규제는 §jurisdiction 재스코프에 포함.

## 7. 연동

- `onboarding.onboarding_decision()` → 유저 단계별 지갑/가스/KYC 상태.
- `trust_score`(상환 게이트) + `redemption_epoch`(정산) + onboarding(지갑) = 상환 UX 3종 세트.
- 실 SDK(Sequence/Privy) 연동은 계측 빌드(C1 ②)·본편(C3) 단계.
