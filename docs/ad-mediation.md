# 광고 수요 집약 (Ad Mediation) — 설계서

> **한 줄**: QuestFi는 특정 광고사에 묶이지 않는다. CPQ는 **수요 소스 무관 추상화**이고, QuestFi는
> **모든 광고 수요(CPC·CPM·CPCV·오퍼월·직판)를 한데 모아 "완료당 매출"로 정규화하는 미디에이션 레이어**다.
> 구현: `ad_mediation.py` · 테스트: `test_ad_mediation.py` (15개 통과).

## 1. 왜 "다 싸잡아먹기"가 경제의 핵심인가

`cpq_model.py`는 **단일 글로벌-혼합 소스는 손익분기에 아슬아슬**하다고 했다. 소스를 쌓으면 두 지표가
동시에 올라 그 선을 넘는다:

1. **Fill률** = `1 − Π(1 − fᵢ)` — 소스가 많을수록 채워지는 노출이 늘어난다 (§8 fill_rate 40%→85% 레버).
2. **eCPM** — 소스들이 **경쟁 입찰**하면 낙찰가가 오른다 (실시간 미디에이션·헤더비딩이 존재하는 이유).

### 모델 결과 (`ad_mediation.py`, per-source median eCPM $8·fill 55%)

| 소스 수 | fill률 | 유효 eCPM | CPQ (1유닛) | 손익분기 | 목표 |
|---:|---:|---:|---:|:--:|:--:|
| 1 | 55% | $5.22 | $0.0052 | · | · |
| 2 | 80% | $8.64 | $0.0086 | ✓ | · |
| 4 | 96% | $12.48 | $0.0125 | ✓ | · |
| 8 | 100% | $16.52 | $0.0165 | ✓ | · |
| 10 | 100% | $17.83 | $0.0178 | ✓ | · |

> **판정**: 단일 소스는 손익분기 미달, **소스를 다 싸잡으면 fill·eCPM이 함께 올라 손익분기를 넉넉히 통과.**
> 목표 $0.03은 여기에 **퀘스트당 광고 유닛 >1**("부품 스캔 N회", `ad_units_per_quest`)이나 **tier-1 트래픽**을
> 얹으면 도달 (8소스 × 2유닛 = $0.033, 목표 통과 — 테스트로 검증).

## 2. ⚠️ 컴플라이언스 제약 — "클릭당 돈"의 함정

"다 싸잡자"에서 **가장 중요한 안전선**. 유저에게 보상을 주고 **표준 네트워크 광고를 "클릭"하게 하는 것**은
Google/AdMob 등 다수 정책의 **무효 트래픽(invalid traffic) 위반**이며 계정 밴 리스크다.

| 프리미티브 | 인센티브 허용? | QuestFi 매핑 |
|---|---|---|
| **Rewarded video (CPCV)** | ✅ (시청 보상 명시 허용) | "부품 스캔"의 1차 소스 |
| **Offerwall (CPA/CPI)** | ✅ (액션·설치 보상) | 퀘스트 = 액션 완료 |
| **직판 CPQ** | ✅ (우리 규칙) | Tier 2, 완료 프리미엄 |
| Programmatic (CPM) | 조건부 (비인센 노출) | 배경 노출, 클릭 유도 금지 |
| **표준 CPC 클릭 보상** | ❌ 정책 위반 다수 | **인센티브 클릭 금지** |

> **설계 원칙**: "부품 스캔"은 **시청 완료(rewarded)·액션 완료(offerwall)·직판 CPQ**에 기댄다.
> CPC 네트워크의 클릭을 보상하지 않는다. 유저 화면 표현은 §12(광고/Ads 금지)대로 게임 언어로.

## 3. 아키텍처

```
[수요 소스들]                    [정규화]              [경매]           [렌더]         [게이트]
AdMob rewarded ─┐
Unity/LevelPlay ─┤
AppLovin MAX    ─┼─→ 각 소스 native 단위  ─→  revenue-per-quest  ─→  1st-price   ─→ "부품 스캔"  ─→ 안티봇
ironSource      ─┤    (CPCV/CPA/CPM/CPC)      로 정규화              입찰(bidding)     UX(§12)      신뢰 게이트
Offerwall(Tapjoy)┤                                                                              (trust_score)
직판 CPQ        ─┘                                                                                   ↓
                                                                                              검증된 완료 → Spark
```

- **정규화**: 소스가 뭘로 지불하든(시청·액션·노출) → **완료당 기대 매출**로 환산해 CPQ 단일 뷰로.
- **경매 > 워터폴**: 가능하면 실시간 입찰(모든 소스 동시 경쟁) → 낙찰가 최대화. 워터폴은 폴백.
- **품질/사기 게이트**: 소스가 다양 = 사기·품질도 다양. 소스별 품질 스코어 + `trust_score.py`로 봇 완료를
  상환 풀에서 제외. 광고주 ROI(§1)를 지키는 지점.

## 4. Fill·품질의 이중성

소스를 늘리면 fill은 오르지만 **저품질 소스가 섞일 위험**도 는다. 그래서:
- 소스별 **eCPM 하한(floor)** 으로 저가 소스 컷.
- 소스별 **품질 점수**(뷰어빌리티·완료율·사기율) 추적 → 나쁜 소스 강등.
- 봇 필터(§트러스트)와 결합 → "fill만 부풀린 가짜 완료"가 CPQ 측정·상환에 못 들어옴.

## 5. 로드맵 (CPQ 실측과 연동)

1. **Tier 1**: rewarded + offerwall SDK **2–3개** 미디에이션으로 시작 → `ad_mediation` 모델 실측 보정
   (`base_ecpm`·`per_source_fill`을 실데이터로 교체).
2. **확장**: bidding 미디에이션(AppLovin MAX / LevelPlay)로 소스 8–10개 경쟁.
3. **Tier 2**: 직판 CPQ 수요 추가 → 완료 프리미엄(§1 테제) 상업 검증.

## 6. 결정

- **광고 수요 = 멀티소스 미디에이션.** CPQ는 소스 무관 추상화. 단일 네트워크 종속 금지.
- **인센티브는 시청·액션에만**, 클릭 보상 금지(정책·밴 리스크).
- 소스 다양성이 fill·eCPM을 손익분기 위로 밀어올리는 **경제적 필수 요소**다.
